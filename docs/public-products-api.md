# Барааны Public API v1

Үндсэн хаяг: `https://crm.antmall.mn/api/public/v1`

Хэрэглэгчийн нэвтрэлт шаардахгүй. Бүх GET/HEAD хүсэлтэд тогтмол `X-Token` header шаардлагатай, үүнд OpenAPI тодорхойлолт мөн орно. OPTIONS preflight токен шаардахгүй бөгөөд барааны мэдээлэл буцаахгүй. Бараа, үнэ, үлдэгдлийг API-аар өөрчлөх боломжгүй.

```http
X-Token: <INTEGRATION_TOKEN>
```

Токен нь хугацаагаар автоматаар солигдохгүй. Сервер кодод зөвхөн SHA-256 хэш нь тогтмол `const` хэлбэрээр хадгалагдана. Жинхэнэ токеныг Git, URL query, логт оруулахгүй. Токен эзэмшигч бүх нийтэд зориулсан барааны мэдээллийг уншина; тусдаа хэрэглэгчийн эрх биш. Сайтын backend-ээс header нэмэх нь тохиромжтой — browser JavaScript-д оруулбал сайтад зочилсон хүн токеныг харж чадна.

CORS нь `X-Token` header-ийг зөвшөөрнө, cookie шаардахгүй. Буруу эсвэл дутуу токентой хүсэлтэд өгөгдлийн сан уншихаас өмнө HTTP 401 буцаана. URL параметр болон Bearer header-ийг токены оронд хүлээж авахгүй.

## Хаягууд

```text
GET /products
GET /products?in_stock=true&limit=100&page=1
GET /products?q=iPhone&brand=APPLE
GET /products?site_product_id=35374
GET /products/{id}
GET /products/{sku}
GET /openapi.json
```

`page` нь 1–10000, `limit` нь 1–100 (анхны утга 25). `q` нь нэрийн хэсэг, эсвэл бүтэн CRM ID/SKU/баталгаажсан сайтын код. `brand`, `category` яг таарсан утгаар шүүнэ. `in_stock=true` үлдэгдэлтэй, `false` үлдэгдэлгүй барааг харуулна. Оруулахгүй бол хоёуланг буцаана. Хуудас хооронд барааны ID-аар тогтвортой эрэмбэлнэ. Давхардсан, үл мэдэгдэх, буруу параметрт HTTP 400 буцаана.

`site_product_id` нь идэвхжүүлсэн, одоогийн сайтын каталогийн кодтой таарсан холбоосоор шүүнэ. Холбоос байхгүй бол хоосон жагсаалт буцаана; нэрээр тааж бараа сонгохгүй.

## Бүтэц

```json
{
  "data": {
    "id": "p_example",
    "sku": "ANT-000123",
    "name": "iPhone 17 Pro",
    "brand": "APPLE",
    "category": "Гар утас",
    "capacity": "256GB",
    "color": "Blue",
    "variant": "New",
    "image_url": null,
    "stock": {"quantity": 3, "in_stock": true, "scope": "all_warehouses"},
    "prices": {
      "currency": "MNT",
      "credit": {"min": 4500000, "max": 4500000},
      "cash": {"min": 4200000, "max": 4200000}
    },
    "site": null
  },
  "as_of": "2026-09-23T04:00:00.000Z"
}
```

Энэ нь бүтцийг тайлбарласан жишээ, бодит бараа/үнэ биш. Жагсаалтын `data` нь массив бөгөөд `pagination` талбарт `page`, `limit`, `total`, `total_pages`, `has_more` байна.

## Код ба ширхэгийн ялгаа

Нэгдсэн SKU нь `ANT-000123` хэлбэртэй. Бүтээгдэхүүний бүлэгт нэг удаа оноосон дугаарыг өгөгдлийн санд хадгалж, дахин ашиглахгүй. Ижил бүлэгт шинэ IMEI нэмэхэд SKU хэвээр байна. Өнгө/багтаамж зэрэг бүтээгдэхүүний бүлгийг тодорхойлох мэдээлэл өөрчлөгдөж шинэ бүлэг үүсвэл тэр бүлэг өөр SKU авна. Өмнөх `CRM-{product_key}` кодоор дэлгэрэнгүй авах, хайх боломжийг хадгалсан. Одоогийн CRM ID, барааны хуучин код, сайтын `ANTM-…` кодыг дарж өөрчлөхгүй. Хуучин `product_key` хоосон бүртгэлд тухайн бүртгэлийн ID-г ашиглана. Хувилбарын мэдээлэл дутуу тул CRM-д тусдаа байгаа бүлгийг энэ API автоматаар нэгтгэхгүй.

Хэд хэдэн IMEI-тай ширхэг нэг бүтээгдэхүүний бүлэгт байж болно. Public API нь нийт тоог харуулна. Бүрэн болон маскалсан IMEI, баркод, дотоод ширхэгийн ID, нийлүүлэгч, өртөг, ашиг, хэрэглэгчийн мэдээлэл гаргахгүй. IMEI олголт нь нэвтэрсэн CRM-ийн үйлдэл хэвээр байна.

## Үлдэгдэл ба үнэ

Бүлгийн идэвхтэй бүртгэлүүдийн бүх агуулахын хөдөлгөөний тоо ширхэгийг нийлүүлнэ. Сөрөг нийлбэрийг нийтэд 0 гэж харуулна. Хайлтыг нийлбэр тооцсоны дараа хийдэг тул хэсэгчилсэн хайлт үлдэгдлийг бууруулахгүй. 0 үлдэгдэлтэй бүлгүүд анхдагчаар орно. Идэвхтэй бүртгэлгүй бүлэг нийтэд гарахгүй, дэлгэрэнгүй нь 404 буцаана.

Зээл болон бэлэн үнийг тусад нь MNT-өөр, min/max хүрээгээр буцаана. Бүлгийн аль нэг идэвхтэй бүртгэлд тухайн үнэ байхгүй/0 бол тэр үнийн объект `null`; дутуу үнийг таамаглахгүй. Бэлэн үнийг үндсэн үнээр орлуулахгүй. Бүртгэлүүдийн үнэ ялгаатай бол захиалга батлахаас өмнө бодит үнийг шалгана.

`as_of` нь хариу үүсгэсэн UTC цаг. Хариунд `Cache-Control: private, no-store`, CDN-д `no-store` ашиглана. Токентой хүсэлтийн хариуг токенгүй хүсэлтэд кэшээр өгөхгүй. Энэ API нь үлдэгдэл унших зориулалттай, бараа нөөцлөх/захиалга батлах үйлдэл биш. Сайтын захиалгыг CRM-д бүртгэж байж үлдэгдлийн эх сурвалж зөв байна.

Барааг бүрэн идэвхгүй болгосон эсвэл бүлэг өөрчлөгдсөн үед жагсаалтаас алга болж болно. Синк хийдэг хэрэглэгч бүх хуудсыг тогтмол тулгаж, өмнө холбосон ID нь 404 болсон бол автоматаар өөр бараанд холбохгүй, нягтлалд шилжүүлнэ.

## JavaScript

```js
const response = await fetch(
  'https://crm.antmall.mn/api/public/v1/products?limit=100&page=1',
  { headers: { 'X-Token': process.env.ANTMALL_PUBLIC_API_TOKEN } }
);
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const result = await response.json();
for (const product of result.data) {
  console.log(product.sku, product.stock.quantity);
}
// pagination.has_more үнэн бол дараагийн хуудсыг авна.
```

Энэ нь сервер талын JavaScript жишээ. Алдаанууд: `401 UNAUTHORIZED`, `400 INVALID_QUERY/INVALID_ID`, `404 PRODUCT_NOT_FOUND`, `503 SERVICE_UNAVAILABLE`. Алдааны хариунд SQL, орчны тохиргоо, токен агуулахгүй, кэшлэхгүй.
