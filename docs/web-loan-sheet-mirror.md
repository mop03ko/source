# Direct web requests: Google Sheet mirror

CRM remains the primary receiver. A systemd worker mirrors new `web_loan_requests` into the existing spreadsheet `1M2axJmy54eQ7ksUS-6bZLACftqkWHFQ4tj82h88DPbk`, tab ID `2042487499` (`Antmall.mn web Хүсэлтүүд`). Website responses do not wait for Google. The timer checks 30 seconds after each completed run; Google outages can delay export without losing CRM requests.

The user authorized backfilling missing direct requests on September 29, 2026. Initial verification covered 30 real requests, including two newly received during deployment. Every exported ID occurs exactly once and all four personal/product fields match CRM. No test lead or SMS was generated by this work.

Columns A:E retain timestamp (Ulaanbaatar), phone, registration, product, name. Columns F:Z are left blank on new rows for the existing workflow. Column AA stores `CRM Request ID`. RAW input preserves leading zeroes and prevents formula execution. New requests use a targeted RAW values.update into the first fully empty existing row after the header, without inserting or shifting rows. Every allocated column is scanned in bounded batches using userEnteredValue and note: formulas (including empty results), whitespace, zero, false, notes and isolated CRM IDs reserve a row. The candidate is checked again immediately before writing. If capacity is exhausted, 100 rows are added at the bottom. The response range and all exported fields are verified. The MySQL lock serializes workers; Google Sheets has no conditional empty-row update, so manual edits during the short check/write interval cannot be locked out.

A later audit found 27 existing records with displaced markers and two missing data payloads. Those historical discrepancies require separate repair and are not changed by the empty-row allocator.

The worker holds a MySQL named lock. An activity `sheet-<lead ID>` tracks each export. On retry it first searches the Sheet for the marker, or reconciles an exact legacy timestamp + phone + registration + product + name match. Completed exports are recorded as readable notes by `AntMall Sheet`. A pending claim is written before writing. Timeouts/5xx leave `sheet_uncertain`; later runs reconcile visible markers but never blindly repeat uncertain writes. Operators must inspect unresolved uncertain exports before manually resetting them. Definitive rejected requests remain pending for later retry.

Service: `antmall-web-loan-sheet.service`; timer: `antmall-web-loan-sheet.timer`. Script: `/srv/antmall-crm/integrations/web-sheet/mirror.mjs`; dependencies point at the current CRM runtime. Private credentials are in `/srv/antmall-crm/shared/web-sheet.env`, root:antmall-crm mode 640, and reuse the existing website Sheet service account. Deployment units are in `deploy/`. Install the script after code changes; changing the current CRM symlink alone does not update this standalone worker.

Sheet connection 2 remains disabled and `CRM_DIRECT_WEB_LOANS=true` remains set. Do not re-enable Sheet-to-CRM ingestion for these mirrored rows, as they already exist in CRM. This process mirrors intake only; later CRM edits/status changes are not propagated to existing Sheet rows.

Validation: `node tests/web-loan-sheet-mirror.test.mjs`; production row readback, all-field comparison, duplicate-marker check, repeated no-op run, and two live newly received requests. Inspect `journalctl -u antmall-web-loan-sheet.service` for aggregate counts; logs exclude credentials and customer data. To pause exports, stop the timer. Existing CRM/Sheet records remain intact.
