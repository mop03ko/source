# Агуулахын UI/UX аудит

Огноо: 2026-09-21. Суурь commit: `c936b0c`. Зорилго: агуулахын өдөр тутмын ажлыг хурдан, ойлгомжтой, алдаа гаргахад хэцүү болгох.

## Гол дүгнэлт

Одоогийн системд барааг нэгтгэх, IMEI/баркод ялгах, хоёр үнэ, үлдэгдлийн тайлан, график, CSV, бөөн сонголт зэрэг хэрэгтэй суурь бий. Гол асуудал нь боломж дутсанд бус, мэдээлэл ба үйлдлийн дараалалд байна. Жагсаалтаас өмнөх хэсэг хэт өндөр; тооллогын эцсийн баталгаажуулалт хангалтгүй; бараа → дугаар → хөдөлгөөн гэсэн урсгалд буцах холбоос алга.

18 сайжруулах зүйл тодорхойлов: P1 — 6, P2 — 10, P3 — 2. P1 нь эхэлж засах ажлын урсгал/ойлголтын асуудал; P2 нь өдөр тутмын үр ашиг, хүртээмж; P3 нь дараагийн сайжруулалт. Энэ нь батлагдсан 18 программын гэмтэл гэсэн үг биш. Код, дэлгэцээр батлагдсан ажиглалт ба санал болгосон загварыг доор ялгасан. Мэдээлэл устсан, үйлдвэрлэлийн доголдол гарсан гэсэн P0 нотолгоо энэ аудитаар тогтоогоогүй.

## Хамрах хүрээ, арга

- Бараа/үлдэгдэл, үлдэгдлийн тайлан, худалдан авалт, борлуулалт, хөдөлгөөн, тооллого гэсэн зургаан таб.
- Бараа нэмэх/засах, нэгтгэсэн бараа болон дугаарын дэлгэрэнгүй, бараа сонголт, агуулах нэмэх, худалдан авалт/борлуулалт/шилжүүлэг, буцаалт, импорт, платформын тохиргоо, тооллого үүсгэх/дэлгэрэнгүй/календарь.
- 1440×1000, 768×1000, 390×1000 хэмжээтэй Chrome; локал тусгаарласан туршилтын өгөгдөл. Жинхэнэ үйлдвэрлэлийн мэдээллийг өөрчлөөгүй.
- Зургаан таб, найман маягтын responsive харагдац; эх кодын урсгал, төлөв, хүснэгт, маягт, эрхийн харагдац; өмнөх үйлдлийн browser тестүүд.
- Screenshot ба DOM нотолгоо: [аудитын хавтас](../artifacts/inventory-ui-ux-audit-2026-09-21/). Дахин ажиллуулах: `node scripts/inventory-ui-ux-audit.mjs` (бэлэн Next build шаардлагатай).
- [Бараа нэгтгэл/дугаарын шалгалт](../artifacts/inventory-products-audit/evidence.json), [борлуулалт/тайлангийн шалгалт](../artifacts/inventory-audit/evidence.json).

Хязгаар: энэ нь хэрэглэгчтэй хийсэн usability судалгаа, бүх role-оор гүйцэтгэсэн E2E аудит, WCAG нийцлийн гэрчилгээ биш. Үндсэн browser сесс админ эрхтэй. Буцаалтын маягт, импортын файл боловсруулалт, finalize-ийн бизнес дүрмийг голчлон кодоор үнэлсэн; шинэ аудитаар бодит импорт/тооллогын тохируулга хийгээгүй. Олон мянган мөрийн хурд, жинхэнэ iOS/Android гар, screen reader, өнгөний контрастын тоон хэмжилтийг тусдаа баталгаажуулах шаардлагатай. Доорх хурдтай холбоотой зүйлс нь кодын ажиглалт; үйлдвэрлэлийн milliseconds хэмжилт биш.

Browser шалгалтын эцсийн үр дүн: **42 screenshot**, зургаан таб × гурван өргөн, найман маягт × хоёр өргөн, нэмэлт тооллогын дэлгэрэнгүй/календарь, хүснэгт, хайлтын хоосон ба холболтын алдааны төлөв. Runtime exception болон хуудасны нийт өргөний халилт илрээгүй. Барааны эхний мөрийн дээд байрлал **1023.64px**, viewport өндөр 1000px гэж хэмжигдсэн. Хайлтын API-г зориуд хаахад ойлгомжтой алдаа, «Дахин оролдох» товч гарсан нь сайн тал. Энэ нь дотоод хүснэгтийн хөндлөн scroll, гарын навигацийн дутагдлыг үгүйсгэхгүй. ## Эхэлж засах P1 асуудлууд

### 01. Гол жагсаалт эхний дэлгэцээс шахагдсан

**Ажиглалт:** 1440×1000 дээр барааны хүснэгтийн толгой дэлгэцийн доод захад ирж, эхний мөр харагдахгүй. 390 дээр бүр ч олон удаа доош гүйлгэнэ. Хуудасны «Агуулах» гарчгийн дараа «Агуулахын удирдлага» тайлбар давтагдаж, metrics, filters, catalogue switch, grouping, commands, хоосон bulk bar дараалан орсон.

**Нөлөө:** бараа хайх, үлдэгдэл шалгах үндсэн ажлын өмнө хэрэглэгч удирдлагын хэсгээр удаан дамжина.

**Шийдэл:** гарчиг нэг; гол «Бараа нэмэх» товчийг гарчигтай зэрэгцүүлнэ. Хайлт + агуулах + нэмэлт шүүлтүүр нэг мөр. Үзүүлэлтүүдийг намхан summary болгоно. Grouping-ийг «Харагдац» хэсэгт, агуулах/импорт/тохиргоог хоёрдогч менюд байрлуулна. Сонголтын ажиллагааны зурвасыг сонголт хийсний дараа гаргана; хуудас сонгох checkbox хэвээр үлдэнэ.

**Шалгуур:** 1440×900 дээр 5-аас доошгүй мөр; 390×844 дээр эхний барааны нэр, үлдэгдэл нэмэлт гүйлгэлтгүй харагдах зорилт. Одоогийн screenshot: [desktop](../artifacts/inventory-ui-ux-audit-2026-09-21/items-1440.png), [mobile](../artifacts/inventory-ui-ux-audit-2026-09-21/items-390.png). Код: `app/inventory-panel.tsx`.

### 02. Тооллогын тохируулгыг дүнгээр нь хянах алхамгүй

**Ажиглалт:** «Тооллого дуусгаж, зөрүүг тохируулах» нь шууд `save_lines` → `finalize` дуудна. Мөрүүдийн зөрүү харагддаг боловч эцсийн нийлбэр, дуусаагүй мөр, агуулах, тохируулгын нөлөөг нэг дор шалгах шат алга.

**Шийдэл:** «Зөрүү хянах» → тусдаа баталгаажуулах Modal. Тоолсон/тоолоогүй мөр, нэмэгдэх/хасагдах ширхэг, агуулах, зөрүүтэй мөрүүдийг харуулна. Өртгийг баталгаатай тооцож чадах үед л харуулна. «X мөрийн зөрүүг баталгаажуулах» гэсэн тодорхой төгсгөлийн үйлдэл хэрэглэнэ. Backend-ийн version/stock validation-ийг хэвээр хадгална.

**Шалгуур:** дуусаагүй мөрөөс шууд тухайн мөр рүү очдог; цуцлахад бүх оруулсан утга хадгалагддаг; эцсийн тохируулга зөвхөн дүнг хянасны дараа хийгддэг. Код: `app/inventory-counts-panel.tsx` (`finalize`).

### 03. Тооллого хийх орчин олон бараанд тохирохгүй

**Ажиглалт:** 580px Drawer дотор даалгаврын урт засах маягт, бүх барааны мөр, тоолох input, хадгалах, дуусгах, тэмдэглэл, түүх хамт байна. Мөрийн хайлт, «тоолоогүй/зөрүүтэй» шүүлтүүр, ахицын үзүүлэлт байхгүй. Бүх мөрийг нэг дор render хийнэ.

**Шийдэл:** тоолох ажлыг бүтэн өргөнтэй ажлын дэлгэц болгоно. Даалгаврын мэдээллийг эвхэгддэг хэсэгт; голд хайлт/скан оруулах талбар, ахиц, тооллогын Table; доор тогтвортой хадгалах хэсэг. Их өгөгдөлд pagination эсвэл virtual table сонгохдоо оруулсан утгыг хуудас солиход алдахгүй хадгална.

**Шалгуур:** 500+ мөртэй fixture дээр дурын кодыг олж тоолох, зөвхөн зөрүү харах, хадгалсны дараа үргэлжлүүлэх; гар утсанд тоолсон тоо ба нэр нэг харагдацад байна. Код: `app/inventory-counts-panel.tsx`.

### 04. Гар утасны хүснэгтэд чухал дүн хажуу тийш далд байна

**Ажиглалт:** барааны хүснэгт сонголттой нийлээд 9 баганатай; дугаарын Drawer дотор supplier/stock/price хөндлөн scroll шаарддаг. Хуудас өөрөө халихгүй байгаа нь мэдээлэл нэг дор харагдаж байна гэсэн үг биш.

**Шийдэл:** desktop Table-д барааны нэрийг тогтоон барих, мөнгөн дүнг баруун зэрэгцүүлэх, хоёрдогч багана сонгодог болгох. Mobile-д барааны нэр + загвар/өнгө + үлдэгдэл + үнэ бүхий card/list, дэлгэрэнгүйд supplier/cost/IMEI. Дугаарын жагсаалтад IMEI ба үлдэгдлийг хамт харагдуулна.

**Шалгуур:** 390px дээр нэг барааны нэр, үлдэгдэл, үндсэн үйлдлийг хөндлөн гүйлгэлтгүй уншина. Тайлангийн дэлгэрэнгүй хүснэгтэд хөндлөн scroll зөвшөөрч, тогтсон нэрийн багана болон харагдах заагтай байна. Код: `components/ui/table.tsx`, `app/inventory-product-detail.tsx`.

### 05. Бараа → дугаар → буцах урсгал тасардаг

**Ажиглалт:** нэгтгэсэн бараанаас дугаар нээх үед parent Drawer-ийг хаадаг (`setProduct(null)`). Дугаарыг хаахад өмнөх parent-ийн хайлт/хуудас руу биш үндсэн жагсаалтад очно. Нэг барааны хэд хэдэн IMEI шалгахад давтан нээх шаардлагатай.

**Шийдэл:** нэг Drawer дотор дотоод чиглүүлэлт, «← Барааны дугаарууд» буцах холбоос; parent хайлт, pagination, scroll хадгалах. Өөр дээр нь edit Modal давхарлахаас зайлсхийж шаардлагатай үед тэр Drawer-ийн засах төлөв рүү шилжих.

**Шалгуур:** parent-ийн 2-р хуудаснаас дугаар нээж буцахад яг өмнөх хайлт, 2-р хуудас, scroll сэргэсэн байна. Код: `app/inventory-panel.tsx`, `app/inventory-product-detail.tsx`.

### 06. Нэгтгэсэн бараа, дугаарын бүртгэл, ширхэгийн утга холилдсон

**Ажиглалт:** нэгтгэсэн каталогт «Барааны төрөл», raw list/report-д «барааны бүртгэл», pagination-д ерөнхий «бүртгэл» хэрэглэнэ. Нэг мөр олон ширхэг байж болно. Parent-ийн `min_stock` нь хүүхэд бүртгэлийн босгуудын нийлбэр. Үлдэгдэл 0, босго 0 мөр ч «Доод үлдэгдэлд хүрсэн» тоонд орно.

**Нөлөө:** хэдэн бүтээгдэхүүн, хэдэн дугаар, хэдэн ширхэг байгаа болон юу нөхөн татахыг андуурч болно. Энэ нь тооцоолол эвдэрсэн гэхээсээ одоогийн нэгтгэлд нэр томьёо/босго тохироогүй асуудал.

**Шийдэл:** «Бүтээгдэхүүн: X · Дугаарын бүртгэл: Y · Үлдэгдэл: Z ш» гэж ялгана. «Үлдэгдэлгүй» ба «Нөхөн татах»-ыг тусад нь үзүүлнэ. Дахин захиалах босгыг загвар+хувилбар/агуулахын ямар түвшинд удирдахыг нэг мөр бизнес дүрэм болгоно; одоогийн босгыг дур мэдэн шилжүүлэхгүй.

**Шалгуур:** 2 IMEI + 5 ширхэгтэй нэг batch бүхий fixture-д бүтээгдэхүүн, бүртгэл, ширхэгийг тус тус зөв тайлбарлана. Код: `app/api/inventory/route.ts:42`, `app/inventory-panel.tsx`.

## Санал болгож буй дэлгэцийн бүтэц

Desktop: **нэг гарчиг + гол үйлдэл → зургаан таб → намхан summary → хайлт/агуулах/шүүлтүүр → хүснэгт → pagination**. Тайлангийн табд summary-ийн дараа график/жагсаалтын switch; тооллогыг тусгай ажлын дэлгэцээр нээнэ. Каталогийн баганын үндсэн эрэмбэ: бараа/хувилбар → үлдэгдэл → үндсэн/бэлэн үнэ → нийлүүлэгч → бусад.

Mobile: **гарчиг + гол үйлдэл → одоогийн таб → хайлт + шүүлтүүр товч → барааны card list**. Нэмэлт шүүлтүүр нь Drawer; нэг барааны нэр хоёр мөр хүртэл, үлдэгдэл шууд харагдах, үнэ тусдаа мөр. IMEI/баркодыг хуулж авах үйлдэлтэй болгоно. Тоолох үед дэлгэцийн зайг metrics/тайлбараас илүү бараа ба тоон input-д өгнө.

Харагдах загвар: одоогийн брэндийн өнгийг хадгалж, нэг бүсэд нэг гол CTA; 8/16/24px зайны шатлал; мөнгөн дүнд tabular numerals ба баруун зэрэгцүүлэлт; статусыг өнгө+текстээр; desktop үндсэн текст 14px, mobile input 16px-ээс эхлэх загварын санал. Touch target 44px-ийг төслийн зорилт болгоно. Эдгээр нь шинэ дизайны санал болохоос одоогийн бүх хэмжээ стандарт зөрчсөн гэсэн дүгнэлт биш.

## Ant Design ашиглах шийдэл

Төсөл Ant Design-ийг аль хэдийн ашиглаж байна. Гол сайжруулалт нь компонентын нэр солих биш, бодит dataSource/columns болон төлөвийн удирдлагатай зөв холбох юм. Одоогийн `components/ui/table.tsx` нь Ant Table-ийн body/header-ийг custom children-ээр орлуулж байгаа тул fixed columns, responsive columns, sorting, virtualization-ийг шууд бүрэн ашиглахад refactor шаардлагатай.

| Зорилго | Компонент, ашиглалт |
|---|---|
| Табын хүртээмж | `Tabs`; сонголт, overflow, panel холбоос. [Албан баримт](https://ant.design/components/tabs/). Keyboard acceptance-ийг [WAI-ARIA Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)-тай тулгана. |
| Мэргэжлийн хүснэгт | `Table`: бодит columns/dataSource, rowSelection, fixed нэрийн багана, responsive secondary columns, sorter, sticky header, summary. Их count list-д virtual тохиромжтой эсэхийг туршина. [Албан баримт](https://ant.design/components/table/). |
| Импортын үе шат | `Steps`: файл, шалгалт, баталгаажуулалт, үр дүн. [Албан баримт](https://ant.design/components/steps/). |
| Маягт ба дэлгэрэнгүй | Төсөлд байгаа `Modal`, `Drawer`, `Descriptions`, input/select суурийг хадгалж, тогтсон footer, тодорхой бүлэглэл нэмэх. |
| Төлөв ба тойм | Төсөлд байгаа `Alert`, `Empty`, `Statistic`, `Card`, `Tag`, `Segmented`, `Progress`-ийг нэг ижил утгаар хэрэглэх. Skeleton/loading нь empty-ээс тусдаа байх. |
