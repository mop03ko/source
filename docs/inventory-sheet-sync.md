## Ажиллуулах

```powershell
node --env-file=.env.local scripts/sync-inventory-sheet.mjs
node --env-file=.env.local scripts/sync-inventory-sheet.mjs --apply --digest=<preview-д гарсан digest>
node tests/inventory-sheet.test.mjs
```

Эхний команд зөвхөн тулгалт хийнэ. Хоёр дахь команд тухайн эх сурвалж өөрчлөгдөөгүй үед шинэчилнэ.

CRM: **Агуулах → Sheet синк**. Админ, удирдлага, ахлах эх сурвалж сонгож, тулгалт үзээд шинэчилнэ. Тулгалтын дараа Sheet эсвэл CRM үлдэгдэл өөрчлөгдвөл API 409 буцааж дахин тулгахыг шаардана. Автомат хуваарь асаагаагүй. Нэвтрэлт, role болон same-origin шалгалт серверт хийгдэнэ. Түлхүүр браузерт дамжихгүй.

## Дүрэм

- Барааны код нэг утгаар таарч, нэр, IMEI, багтаамж, өнгө тохирсон идэвхтэй бүртгэлийг шинэчилнэ.
- P баганын эцсийн үлдэгдэл хүртэл зөрүүний хөдөлгөөн нэмнэ; эхний үлдэгдэл болгон давхар нэмэхгүй.
- Арын агуулах → Olympic Galleria; Заал → Үзүүлэн; Урд агуулах → Сонсголон агуулах.
- Давхардсан код, буруу тоо, өөр агуулахт үлдэгдэлтэй бүртгэл, танигдаагүй бараа болон мэдээллийн зөрчлийг тайланд үлдээнэ. Sheet-д байхгүй CRM барааг тэглэхгүй. Union-ийн тусдаа үлдэгдлийг устгахгүй.
- Барааны үнэ, брэнд, нийлүүлэгч, SKU-г өөрчлөхгүй. Буурах тооны өртгийг CRM-ийн дундаж өртгөөр хасна; нэмэгдэх тоог одоогийн дундаж өртгөөр, үлдэгдэлгүй үед Q баганын өртгөөр үнэлнэ.
- Өөрчлөлт `count_adjustment` хөдөлгөөнөөр мөр, эх сурвалж, service account, өмнөх/дараах тоотой хадгалагдана.
- Бүх хөдөлгөөн болон эх сурвалжийн digest нэг transaction-д хадгалагдана. Яг ижил эх сурвалжийг дахин ажиллуулахад дараа нь CRM-д бүртгэсэн борлуулалтыг буцааж нэмэхгүй.
- Эх сурвалжийн шинэ хувилбарыг дахин хэрэгжүүлэхэд Sheet-ийн тоо давамгайлна. Иймээс CRM-ийн борлуулалт Sheet-д туссан эсэхийг шалгаж байж дараагийн шинэчлэлтийг ажиллуулна.
- `outputs/inventory-sheet-*` дотор эх сурвалж, CRM-ийн өмнөх төлөв, тулгалт, үр дүн хадгалагдана. Эдгээр нь дотоод өртөг болон IMEI агуулдаг тул нийтэд тараахгүй.
